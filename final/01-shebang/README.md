# UHCON 2026 FINAL — SheBanG 풀이 기록

## 문제 요약

RWX 페이지에 놓인 x86-64 Linux 셸코드가 현재 디렉터리의 `flag` 내용을 stdout으로 출력해야 합니다. 순위 기준은 길이가 아니라 각 바이트 값에 1을 더한 값의 합입니다.

```python
cost = sum(byte + 1 for byte in program)
```

각 스테이지가 끝날 때 AI가 바이트 값 5개를 새로 금지하며 금지는 누적됩니다. 따라서 하나의 최단 셸코드보다, 의미가 같은 여러 인코딩을 즉시 재조합하는 생성기가 중요합니다.

## 기본 전략

`read`와 `write`를 따로 호출하면 파일 디스크립터·버퍼·길이를 다시 옮기는 명령이 많이 필요합니다. 대신 다음 두 시스템콜만 사용합니다.

1. `open("flag", O_RDONLY)`
2. `sendfile(1, fd, NULL, 큰_값)`

`sendfile`의 네 번째 인자인 `r10`에는 현재 스택 주소를 넣습니다. 정수로 해석하면 충분히 크고, 커널은 실제 파일 크기까지만 복사합니다. 이 문제의 cost에서는 0 바이트가 1밖에 들지 않으므로 `and eax,0`의 `25 00 00 00 00`이 놀랍게도 매우 저렴합니다. 이 0을 PUSH/POP으로 `rsi`에 복사하고 `add al,2`로 `SYS_open`을 만듭니다. `open` 뒤에는 `xchg eax,esi` 한 바이트로 fd를 옮기는 동시에 `eax=0`을 얻습니다. `add al,1; push rax; pop rdi`로 stdout을 만들고, 다시 39를 더해 `SYS_sendfile(40)`을 만듭니다. 그 직후 `cdq`로 offset 인자 `rdx=0`을 만듭니다. `open(..., O_RDONLY)`은 세 번째 mode 인자를 사용하지 않으므로 open 시점의 기존 `rdx` 값은 상관없습니다.

금지 바이트가 없을 때의 31바이트, cost 1746 후보는 다음과 같습니다.

```text
68666c6167545f2500000000505e04020f05960401505f04279954415a0f05
```

이후 dirty-register 검증을 유지하면서 cost를 더 낮춘 중간 후보는 35바이트, **cost 1675**입니다.

```text
2500000000040268666c6167545f6b37000f05966b1700446b17010401505f04270f05
```

핵심 개선은 값이 싼 `IMUL r32, [rdi], imm8` 인코딩입니다.

- `6b 37 00`: `[rdi] * 0`으로 `ESI=0`
- `6b 17 00`: `[rdi] * 0`으로 `EDX=0`
- `44 6b 17 01`: `[rdi] * 1`로 `R10D=0x67616c66`; `sendfile` count로 충분히 큼
- `04 01 50 5f 04 27`: `EAX=0`에서 stdout fd 1을 만들고 `SYS_sendfile(40)`으로 증가

길이는 4바이트 늘지만 각 바이트 값의 합이 크게 낮아져 전체 cost는 71 감소했습니다. 모든 일반 레지스터를 비영 난수로 오염시킨 로컬 runner와 실제 Linux 커널에서 모두 flag stdout 출력을 확인했습니다.

마지막으로 `push imm32`가 스택에 만든 `"flag\0\0\0\0"`의 상위 4바이트가 반드시 0이라는 점을 이용했습니다. `IMUL ...,0` 두 개를 더 싼 `AND reg,[rdi+4]`로 바꿔 길이는 그대로 유지하면서 **cost 1667**까지 낮췄습니다.

```text
2500000000040268666c6167545f2377040f0596235704446b17010401505f04270f05
```

- `23 77 04`: `ESI &= dword [RDI+4]` → `ESI=0`
- `23 57 04`: `EDX &= dword [RDI+4]` → `EDX=0`
- 초기 GPR 값과 무관하며 스택의 직접 생성 데이터만 사용

## 금지 바이트 대응

생성기는 완성된 바이트열을 기준으로 금지 집합과 교집합이 없는 후보만 남기고 `cost`, 길이, 이름 순으로 정렬합니다.

- 경로 상수: 직접 PUSH, MOV 후 PUSH, XOR/ADD/SUB 2항 분해
- 포인터 이동: PUSH/POP, MOV, LEA, 중간 레지스터 경유
- 0 생성: CDQ와 RDX 재사용, 즉시값 0, XOR/SUB
- fd 이동: 1바이트 XCHG 또는 PUSH/POP/MOV 조합
- `r10` count: RSP 또는 기존 pathname 포인터, LEA/MOV, 작은 즉시값
- syscall 번호 40: ADD/OR/XOR/MOV/PUSH-POP

`syscall`의 고정 바이트 `0f 05`가 금지될 때는 제출 시점에는 다른 두 바이트인 stub을 RWX 코드 페이지 안에서 XOR 복호화한 뒤 간접 호출합니다. 이 방식은 제출물 어디에도 금지된 `0f`/`05`를 두지 않습니다. `int 0x80` 후보도 준비하지만, 32비트 compat ABI의 포인터가 4 GiB 아래여야 하므로 공식 runner의 매핑을 확인하기 전에는 사용하지 않습니다.

## 검증 원칙

제출 서버는 업로드 순간에 아무것도 검사하지 않고 다음 라운드 채점에서만 결과를 보여 줍니다. 따라서 다음 순서를 지킵니다.

1. 최종 바이트열에 금지 바이트가 없는지 재검사
2. Unicorn에서 레지스터를 오염시킨 상태로 syscall 인자와 출력 검증
3. 실제 Linux 커널을 사용하는 로컬 runner에서 stdout 비교
4. 공식 runner가 확보되면 동일한 셸코드를 다시 실행
5. 그 뒤에만 마지막 제출물을 교체

## 운영상 남은 외부 입력

공개 아레나는 상태·금지 바이트·점수만 인증 없이 제공합니다. 실제 제출에 필요한 팀 토큰은 기존 CTFd 인증 세션으로 launch 리다이렉트를 따라가 메모리에서 읽었습니다. 토큰은 코드·명령행·로그·Write-up에 저장하지 않습니다. 자세한 웹/TCP 스키마는 `PROTOCOL_KO.md`에 정리했습니다.

따라서 로컬 에뮬레이션 수준이 아니라 공식 아레나 러너에서도 `open + sendfile` 전략과 출력 후 fall-through가 유효함을 확인했습니다. 이후 운영은 10초 폴링 모니터가 stage/round와 누적 금지 집합 변화를 감시하고, `payloads.json`에서 가장 싼 호환 후보를 자동 재제출합니다. 상세 시각·응답은 `SUBMISSION_LOG.md`와 `arena.jsonl`에 남깁니다.

정적 변형들이 동시에 막히는 경우에는 `encoded_payload.py`가 정상 종료형 45바이트 본체 전체를 1바이트 XOR로 인코딩합니다. 디코더는 포인터 레지스터, 카운터 설정, 반복 방식, backward/forward CALL 배치를 탐색합니다. 예를 들어 `00 01 02 04 05`를 모두 금지해도 65바이트 cost 5228 후보를 생성했고, `ff 01 02 04 05` 금지에는 forward-CALL과 보정된 포인터 변위를 사용한 67바이트 cost 4301 후보를 생성했습니다. 두 후보 모두 실제 WSL 실행에서 정상 종료와 flag stdout 출력을 확인했습니다.

### 실패에서 확인한 진입 상태 주의점

Stage 1 마지막 라운드 직전 공개 스코어보드의 두 팀이 정확히 22바이트/cost 1289인 것을 보고, `RAX=RSI=RDX=0` 및 스택 최상단 return address를 가정한 동일 cost 후보를 긴급 제출했습니다. 로컬 제로 레지스터 kernel runner는 통과했지만 공식 채점은 `flag 가 stdout 으로 나오지 않았습니다`로 실패했습니다. 길이와 cost만 같아도 바이트열·진입 상태 활용법은 다를 수 있으므로, 이후에는 공식 채점으로 성공한 unknown-register-safe 본체만 생성기의 decoded body로 사용합니다.

Stage 2에서 실제 발표된 첫 금지는 `00 01 04 05 0f`였습니다. 정적 후보가 전부 충돌했지만 전체 XOR 생성기가 65바이트/cost 5228 후보를 즉시 만들어 11:00:24 KST에 접수했고, 동일 바이트의 WSL 정상 종료·flag 출력을 재확인했습니다.

이후 dirty-register-safe decoder/body 배치를 다시 골프해 51바이트/cost 4395 후보로 낮췄고, Stage 2 첫 공식 채점에서 10위·+31.6점으로 성공했습니다. 다음 라운드용으로는 50바이트/cost 4193 후보까지 낮춰 접수했으며 독립 WSL에서도 flag stdout을 재확인했습니다.
